Where C++ came from

The ladder from hardware to language

A computer's hardware understands only electricity — on and off. Everything we write has to be turned into that. Over the years, people built a ladder so that humans could write in something readable and the machine could still run it.

In plain words

Machine language is what the CPU eats. Assembly is machine language with short names instead of numbers. A high-level language lets you write almost-English, and a compiler translates it down the ladder for you.

The four paradigms

A paradigm is simply a way of thinking about what a program is. There are four main ones, and each answers "what is a program?" differently.

ParadigmA program is…Languages
ImperativeAlgorithms + DataC, Pascal, FORTRAN
FunctionalFunctionsLisp, Haskell, ML
ObjectData (objects that carry their own behaviour)C++, Java, Smalltalk
LogicFacts + Rules + QueriesProlog

C++ is mainly in the object paradigm, but it still lets you write imperative C-style code. That is why it is called a multi-paradigm language, and it is also why this course starts with C-style basics before moving to objects.

Who made what

Worth remembering

C++ was created by Bjarne Stroustrup. It began as "C with Classes" — the plan was to keep everything good about C and add the ability to group data and functions together. That is the entire idea of this course.

Why learn C and C++ at all

Your materials give four honest reasons:

  • Core software is written in them. Operating systems, device drivers, databases, browsers and game engines are C/C++ underneath.
  • Core strengths. You get speed and direct control over memory. Very few languages let you decide exactly where each byte lives.
  • A huge community. Decades of libraries, books and answered questions.
  • The STL. The Standard Template Library gives you ready-made lists, maps, sorting and searching so you do not rebuild them.
Careful

The same power is the danger. C++ will happily let you read memory you do not own or forget to release memory you took. The language will not stop you. That is the trade: full control, full responsibility.

Chapter 05

cout, cin and cascading

The output operator

cout is not a keyword or a function. It is a predefined object that stands for the standard output stream — normally your screen. A stream just means a flow of data.

General form
cout << item;
Real example
cout << "Total: ";
cout << 250;
cout << 'A';

The << symbol is the insertion operator, also called the "put to" operator. It takes whatever is on its right and pushes it into the object on its left.

In plain words

Read cout << x; as "put x into the screen". The arrows point in the direction the data travels — towards cout.

The input operator

cin is the matching object for the standard input stream — normally your keyboard.

General form
cin >> variable;
Real example
int number1;
cin >> number1;

The >> symbol is the extraction operator, also called the "get from" operator. The program stops and waits for you to type. Whatever you type is stored in the variable on the right.

Worth remembering
  • cout — standard output stream, uses << — insertion / "put to"
  • cin — standard input stream, uses >> — extraction / "get from"
  • Both live in the iostream header.

Cascading

You do not need a separate statement for each item. Chaining several << or >> in one statement is called cascading.

Cascading both ways
cout << "sum=" << sum << "\n";

cout << "sum=" << sum << "\n" << "average=" << average << "\n";

cin  >> number1 >> number2;

The last line waits for two numbers. You can type them separated by a space or by pressing Enter between them.

A complete program using both

average.cpp
#include <iostream>
using namespace std;

int main()
{
    float number1, number2;

    cout << "Enter two numbers: ";
    cin  >> number1 >> number2;

    float sum = number1 + number2;
    float average = sum / 2;

    cout << "sum=" << sum << "\n"
         << "average=" << average << "\n";

    return 0;
}
Output
Enter two numbers: 12 18
sum=30
average=15
Careful

Use << with cout and >> with cin. Swapping them is the single most common first-week error. A memory hook: the arrows always point away from the thing giving data and towards the thing receiving it.

Chapter 06

namespace std and header conventions

What a namespace is

In C, every library name is global — printf, scanf, stdin all sit in one big shared pool of names. If your own function is also called printf, there is a clash.

C++ solved this by putting the whole standard library inside a named box called std. A box like this is a namespace. The full name of the output object is therefore std::cout.

Without using
  • Write std:: before every standard name
  • std::cout << "Hi" << std::endl;
  • Longer, but never ambiguous
With using namespace std;
  • Write the short name directly
  • cout << "Hi" << endl;
  • Shorter — used all through this course
Without using
#include <iostream>

int main() {
    std::cout << "Hello World in C++"
              << std::endl;
    return 0;
}
With using
#include <iostream>
using namespace std;

int main() {
    cout << "Hello World in C++"
         << endl;
    return 0;
}

Header file conventions

This trips up a lot of people, so here is the whole rule in one table.

C headerC++ header
In a C program Use .h — e.g. #include <stdio.h>. Names are global. Not applicable.
In a C++ program Prefix c, drop the .h — e.g. #include <cstdio>. Names are in std. No .h at all — e.g. #include <iostream>.
Preferred in C++
#include <cmath>   // in C it is <math.h>
...
std::sqrt(5.0);    // needs std::
Allowed, not preferred
#include <math.h> // not in std namespace
...
sqrt(5.0);         // no std:: needed
Careful

Writing a C++ header with a .h — like iostream.h — is wrong. Those forms are deprecated and were removed from the standard long ago. Some old compilers still accept them, which makes the mistake hard to spot. Always write <iostream>, never <iostream.h>.

Part II

Two ways to think about a program

The whole point of this subject. Old-style programs organise themselves around actions. Object oriented programs organise themselves around things.

Chapter 08

Procedure oriented programming

This is how C works. You write a list of instructions, wrap groups of them in functions, and the functions pass data around between themselves.

The shape of such a program

A main program calls some functions. Those functions call other functions. It forms a tree, and this is called a top-down design: you start with the big job and keep breaking it into smaller jobs.

Typical structure
                    Main Program
                    /     |      \
           Function-1  Function-2  Function-3
              \        /    |        /
              Function-4    |   Function-5
              /       \     |    /      \
        Function-6  Function-7   Function-8

Where the data lives

This is the important part. In a procedural program most data is global — it sits outside all the functions, and any function can reach in and change it.

Data and functions in POP
     Global data              Global data
        /    \    \          /    /    \
       /      \    \        /    /      \
   +------------+ +------------+ +------------+
   | Function 1 | | Function 2 | | Function 3 |
   +------------+ +------------+ +------------+
   | Local data | | Local data | | Local data |
   +------------+ +------------+ +------------+
In plain words

Imagine a shared whiteboard in an office. Anyone can walk up and rub something out. It works when there are three people. When there are three hundred, and something on the board is wrong, nobody can tell who changed it.

The six characteristics

  • Emphasis is on doing things — on the algorithm, the sequence of steps.
  • Large programs are divided into smaller programs called functions.
  • Most functions share global data.
  • Data moves openly around the system from function to function.
  • A function transforms data from one form into another.
  • It uses a top-down approach in program design.
Careful — this is the exam answer

If asked "what is the main drawback of procedure oriented programming?", the answer is global data is exposed. Data moves freely, any function can change it, so a bug in one function can break a completely unrelated part of the program. Object oriented programming exists to fix exactly this.

Chapter 09

Object oriented programming

OOP turns the picture inside out. Instead of data floating in the open with functions reaching for it, the data is locked inside a box together with the functions that are allowed to touch it.

The four statements that define OOP

  • OOP treats data as the critical element in program development and does not allow it to flow freely around the system.
  • OOP ties data more closely to the functions that operate on it, and protects it from accidental change by outside functions.
  • OOP allows a problem to be broken into a number of entities called objects, and then builds data and functions around those objects.
  • The data of an object can be reached only by the functions belonging to that object. However, functions of one object can call functions of other objects.

The picture

Organisation of data and function in OOP
      Object A                           Object B
   +------------+                     +------------+
   |    DATA    |                     |    DATA    |
   |      |     |  <-- communicate -->|      |     |
   |      v     |                     |      v     |
   |  FUNCTION  |                     |  FUNCTION  |
   +------------+                     +------------+
          ^                                  ^
           \        +------------+          /
            \       |    DATA    |         /
             \      |      ^     |        /
              ----- |      |     | ------
                    |  FUNCTION  |
                    +------------+
                       Object C

Notice the arrow direction inside each box: the function is the only way in or out. Objects talk to each other by calling each other's functions, never by reaching into each other's data.

In plain words

Think of a bank account. Your balance is the data. You are not allowed to open the bank's database and edit your balance. You must call a function — deposit() or withdraw() — and that function checks the rules first. The data is safe because the only doors into it are guarded.

The seven features of OOP

  • Emphasis is on data rather than procedure.
  • Programs are divided into what are known as objects.
  • Data structures are designed such that they characterise the objects — the data describes the thing.
  • Functions that operate on the data of an object are tied together in the same data structure.
  • Data is hidden and cannot be accessed by external functions.
  • Objects may communicate with each other through functions.
  • New data and functions can be easily added when needed.
Procedure oriented
  • Emphasis on doing (the algorithm)
  • Divided into functions
  • Data is global and shared
  • Data moves openly between functions
  • Top-down design
  • Adding new data means touching many functions
Object oriented
  • Emphasis on data
  • Divided into objects
  • Data is hidden inside objects
  • Data reached only through that object's functions
  • Bottom-up design
  • New data and functions added easily

Chapter 10

The six core ideas

Your materials list six concepts that are used throughout object oriented programming. Here they are, each with a plain definition and an everyday example.

ClassesObjectsInheritanceAbstractionEncapsulationPolymorphism

1 · Class

A class is a user-defined data type that acts as a blueprint for creating objects. It wraps data (called attributes or data members) and the functions that work on that data (called methods or member functions) into a single unit.

A class lets you model a real-world thing, an idea, or an abstract structure in a tidy, organised way. The complete set of data and code of an object can be made into a user-defined data type using a class. Classes are the foundation of object oriented programming in C++.

In plain words

A class is like an architect's drawing of a house. The drawing says every house of this type has a door, three windows and a roof. But you cannot live in a drawing. You have to build an actual house from it.

2 · Object

An object is an instance of a class — the actual thing built from the blueprint. It is a concrete representation of the data and behaviour the class described.

To create an object you first define a class with its attributes and methods, then you instantiate the class — make one or more objects from it. Each object has its own separate set of attributes and can call the class's methods to do work.

In plain words

The class is the drawing. Objects are the actual houses. House number 12 and house number 14 were built from the same drawing, but house 12 can be painted blue and house 14 green — each object keeps its own values.

3 · Encapsulation

Encapsulation means wrapping the data and the functions that act on it into a single unit, and keeping the data hidden from the outside world. It is the mechanism that makes the whole "data cannot flow freely" promise work.

In C++ you do this with the keyword private, which we will meet properly in Chapter 36.

4 · Abstraction

Abstraction means showing only what a user needs and hiding the complicated details behind it. The class gives you a small set of buttons to press and keeps the machinery out of sight.

In plain words

You drive a car with a steering wheel, an accelerator and a brake. You do not need to know how fuel injection works. The car's controls are an abstraction of a very complicated machine.

Encapsulation is how you hide it. Abstraction is why you hide it. They are two sides of one coin, which is why they are so often confused.

5 · Inheritance

Inheritance is the process by which one class can take on the properties and behaviour of another class. The class that gives is the base class; the class that receives is the derived class. The derived class gets everything the base had, and can add more of its own.

This is what gives OOP its reusability — you write the common part once and reuse it in every class that needs it.

Worth remembering

Inheritance is listed as a core concept in your materials, and the protected access specifier exists to support it, but the detailed mechanics of inheritance are not covered in these seven decks. They come in a later part of your syllabus. Know the definition; the code comes later.

6 · Polymorphism

Polymorphism is a Greek word meaning "many forms". In programming it means one name, many behaviours — the same operation behaves differently depending on what it is applied to.

You will meet two forms of it in this course, and both are taught in full here:

FormWhat it meansChapter
Function overloadingSeveral functions share one name; the compiler picks the right one from the arguments.Chapter 35
Operator overloadingAn operator like + is given extra meaning for your own class.Chapter 48
In plain words

The word "run" means different things for a person, a program and a business. Same word, different behaviour, and you work out which is meant from the context. Polymorphism is exactly that idea in code.

Chapter 11

Benefits and applications

What you gain

  • Data security. Data is hidden, so outside functions cannot damage it by accident.
  • Reusability. Through inheritance, code written once is reused in many places.
  • Easy to extend. New data and new functions can be added to a class without disturbing the rest of the program.
  • Manageable complexity. A big problem is broken into objects, each small enough to understand on its own.
  • Maps to the real world. The program's objects match the real things the program is about, so the design is easier to talk about.
  • Easier maintenance. When something is wrong with a car's behaviour, you look inside the Car class and nowhere else.

Where it is used

  • Real-time systems
  • Simulation and modelling
  • Object oriented databases
  • AI and expert systems
  • Neural networks and parallel programming
  • CAD/CAM systems
  • Decision support and office automation systems
Worth remembering

A very common short-answer question is "list any four benefits of OOP". Pick from: data hiding and security, reusability through inheritance, easy extension, reduced complexity, closeness to the real world, easier maintenance. Give one line of explanation for each and you have full marks.

Chapter 17

Storage classes

Besides a data type, every variable also has a storage class. The storage class specifies the lifetime and visibility of a variable within the program.

Lifetime
  • The longevity of a variable
  • How long it stays alive during program execution
  • When is it created, when is it destroyed
Visibility
  • The scope of a variable
  • Which parts of the program can see it
  • Where can you write its name

auto

  • It is the default storage class of any type of variable.
  • Its visibility is restricted to the function in which it is declared.
  • Its lifetime is also limited to the time its container function is executing.
  • It is created as soon as its declaration statement is reached, and destroyed as soon as program control leaves its container function block.

extern

  • An external variable is declared outside of a function but is accessible inside the function block.
  • Also called a global variable; its visibility spreads all across the program.
  • It is accessible by all the functions present in the program.
  • The lifetime of an extern variable is the same as the lifetime of the program.

static

  • A static variable has the visibility of a local variable but the lifetime of an external variable.
  • Once declared inside a function block, it does not get destroyed after the function finishes — it retains its value so it can be used by future function calls.
In plain words

static is the storage class with a memory. An ordinary local variable forgets everything the moment the function ends. A static local variable remembers its value for the next call — useful for a counter that must keep counting.

register

  • Similar in behaviour to an automatic variable, but it differs in where it is stored.
  • Automatic variables are stored in primary memory; register variables are stored in CPU registers, which are much faster.
  • It is not an obligation for a compiler to store a register-type variable only in CPU registers — it is a request, not a command.

Chapter 19

Type compatibility

C++ is very strict with regard to type compatibility compared to C — and there is a specific reason for that strictness.

  • C++ defines int, short int and long int as three different types. They must be cast when their values are assigned to one another.
  • Similarly, unsigned char, char and signed char are considered as different types, although each of these has a size of one byte.
  • In C++, the types of values must be the same for complete compatibility, or else a cast must be applied.
Worth remembering — this is the "why"

These restrictions exist for one reason: to support function overloading. If char and signed char were the same type, the compiler could not tell display(char) apart from display(signed char) and overloading would collapse. Strict types are the price of one name meaning many things. You will see this pay off in Chapter 35.

Chapter 20

Declaring and initialising variables

Declare anywhere

In ANSI C, all variables must be declared before they are used in executable statements — usually right at the top of a block. C++ allows the declaration of a variable anywhere in the scope.

Declaring where you need it
int main()
{
    float x;
    float sum = 0;

    for (int i = 1; i < 5; i++)   // i declared inside the for
    {
        cin >> x;
        sum = sum + x;
    }

    float average;                 // declared halfway down
    average = sum / (i - 1);
    cout << average;

    return 0;
}
In plain words

Declare a variable at the place where you first need it, not at the top. The reader then sees the name and its meaning together, and the variable cannot be misused in the fifty lines before it existed.

Dynamic initialisation

In C, a variable must be initialised using a constant expression, and the C compiler fixes the initialisation code at the time of compilation.

C++ permits initialisation of variables at run time. This is referred to as dynamic initialisation. A variable can be initialised at run time using an expression at the place of declaration.

Initialising with a runtime value
....

....

Worth remembering

Dynamic initialisation is used extensively in object oriented programming. It means you can create exactly the type of object needed, using information that is only known at run time. This idea comes back in Chapter 45 as the dynamic constructor.

Reference variables

A reference variable provides an alias — an alternative name — for a variable that already exists. This is a C++ feature; C does not have it.

How to declare one

A variable is declared as a reference by putting & in the declaration. A reference variable must be initialised at the time of declaration.

General form
datatype  variable_name;
datatype &reference_name = variable_name;
Real example
float  total = 100;
float &sum   = total;

Now sum and total are two names for the same piece of memory. Change one and the other changes, because there is only one variable.

Proof that it is one variable
#include <iostream>
using namespace std;

int main()
{
    int x = 10;
    int& ref = x;      // ref is a reference to x

    ref = 20;          // value of x is now changed to 20
    cout << "x = " << x << '\n';

    x = 30;            // value of ref is now changed to 30
    cout << "ref = " << ref << '\n';

    return 0;
}
Output
x = 20
ref = 30
In plain words

A reference is a nickname. If your name is Rajesh and everyone calls you Raj, there is still only one of you. Writing on Raj's form and writing on Rajesh's form is writing on the same form.

A reference to an array element

Aliasing one slot of an array
int n[10];
int &x = n[8];   // x is now another name for n[8]

The main use: passing arguments to functions

A major application of reference variables is in passing arguments to functions. Normally a function gets a copy of your value and cannot touch your original. With a reference, the function works on your actual variable.

Function that changes the caller's variable
void fun(int &x)      // uses reference
{
    x = x + 10;       // x is incremented, so also m
}

int main()
{
    int m = 10;
    fun(m);           // function call — m becomes 20
    ....
}

References can be created not only for built-in data types but also for user-defined data types such as structures and classes.

A function can also return a reference

Returning a reference
int &max(int &a, int &b)
{
    if (a > b)
    {
        return a;
    }
    else
    {
        return b;
    }
}

Because the return type is int&, this function hands back the variable itself, not a copy — which means you can even write max(x, y) = 0; and it will assign into whichever of x or y was larger.

Careful

Three rules that catch people out:

  • A reference must be initialised when declared. int &r; alone is an error.
  • Once bound, a reference cannot be re-pointed at a different variable. Writing r = y; copies y's value into whatever r already refers to.
  • Never return a reference to a local variable of the function — it dies when the function ends, and you are left pointing at nothing.

The scope resolution operator ::

C++ is a block structured language. The same variable name can be used to mean different things in different blocks — and :: is how you reach past the nearest one.

The problem

The scope of a variable extends from the point of its declaration till the end of the block containing the declaration. So this is perfectly legal:

Two separate blocks
.....
{
    int x = 10;
}
.....
{
    int x = 1;
    .....
}
One block inside another
.....
{
    int x = 10;
    .....
    {
        int x = 1;    // hides the outer x
        .....
    }
}

In the right-hand case, the inner x hides the outer one. In C, the global version of a variable cannot be accessed from within the inner block at all. C++ solves this problem by introducing a new operator, ::, called the scope resolution operator.

General form
:: variable-name

This can be used to uncover a hidden variable. It gives access to the global version of a variable. For example, ::count means the global version of count, and not the local count declared in that block.

A complete program

scope.cpp
#include <iostream>
using namespace std;

int m = 10;          // global m

int main()
{
    int m = 20;      // m local to main
    {
        int k = m;   // takes the value of main's m, which is 20
        int m = 30;  // m local to this inner block

        cout << "We are in the inner block \n";
        cout << "k= "   << k   << "\n";
        cout << "m= "   << m   << "\n";
        cout << "::m = " << ::m << "\n";
    }

    cout << "\n We are in outer block \n";
    cout << "m = "   << m   << "\n";
    cout << "::m = " << ::m << "\n";

    return 0;
}
Output
We are in the inner block
k= 20
m= 30
::m = 10

 We are in outer block
m = 20
::m = 10

Reading the output

  • k = 20 — k was initialised from m before the inner m was declared, so it picked up main's m.
  • m = 30 inside — the innermost declaration wins.
  • ::m = 10 everywhere — :: always jumps straight to the global one, no matter how deep you are.
Worth remembering

:: has a second, much more important job in this course: defining a member function outside its class, written as ClassName::functionName(). Same operator, different use. That form is taught in Chapter 37, and you will use it constantly.

Chapter 24

Memory management: new and delete

We use dynamic allocation techniques when it is not known in advance how much memory space is needed.

Why C++ replaced the C functions

C uses the functions malloc(), calloc(), realloc() and free() to allocate and deallocate memory dynamically.

C++ defines two unary operators, new and delete, to perform the task of allocating and freeing memory in a better and easier way. These operators manipulate memory on the free store, so they are also called free store operators.

Worth remembering — the key sentence

An object can be created by using new, and destroyed by using delete, as and when required. A data object created inside a block with new will remain in existence until it is explicitly destroyed by using delete. The lifetime of such an object is directly under your control and is unrelated to the block structure of the program.

The new operator

General form
pointer-variable = new data-type;
Real example

Declare and allocate together

pointer-variable = new data-type[size];

Chapter 31

Call by value, address and reference

This is one of the most important chapters in the course, and one of the most examined. There are three ways to hand a value to a function, and they behave very differently.

Call by value — the traditional way

In a traditional approach, a function call passes arguments by value:

  • The called function creates a new set of variables and copies the values of arguments into them.
  • The function does not have access to the actual variables in the calling program, and can only work on the copies of values.
  • This mechanism is fine if the function does not need to alter the values of the original variables in the calling program.
Call by value — swap fails
#include <iostream>
using namespace std;

void swap(int a, int b)      // a and b are COPIES
{
    int temp = a;
    a = b;
    b = temp;
}

int main()
{
    int x = 10, y = 20;
    swap(x, y);
    cout << "x = " << x << ", y = " << y;
    return 0;
}
Output
x = 10, y = 20      ← nothing changed!

Call by address — the C solution

Pass the addresses of the variables instead of their values, using pointers.

Call by address — swap works
#include <iostream>
using namespace std;

void swap(int *a, int *b)    // a and b hold ADDRESSES
{
    int temp = *a;
    *a = *b;
    *b = temp;
}

int main()
{
    int x = 10, y = 20;
    swap(&x, &y);            // must write & at the call
    cout << "x = " << x << ", y = " << y;
    return 0;
}
Output
x = 20, y = 10

The provision of the reference variables in C++ permits us to pass parameters to the functions by reference. When we pass arguments by reference, the formal arguments in the called function become aliases to the actual arguments in the calling function.

{

    a = b;
    b = temp;
}

{

    swap(x, y);              // looks exactly like call by value
    cout << "x = " << x << ", y = " << y;

Chapter 32

Inline functions

Functions save memory space, which becomes appreciable when a function is likely to be called many times. But every call costs time. Inline functions are the fix.

What a function call actually costs

Every time a function is called it executes instructions such as:

  • Jumping to the function
  • Saving registers, pushing arguments into the stack
  • Returning to the calling function

Spelled out in more detail, this is:

StepWhat happens
Function call overheadThe program needs to push arguments onto the stack, transfer control to the function, execute the function code, and then return control to the caller.
Stack operationsPushing and popping function parameters and return addresses, which can be relatively costly in terms of execution time.
Context switchingThe CPU needs to save the current state (context) and restore it after the function call.

When a function is small, a substantial percentage of execution time may be spent in such overheads.

The old solution: macros — and why they are bad

A macro
#define Square(x) (x*x)

int y = Square(3+1);   // expands to (3+1*3+1) = 7, NOT 16!

Use of macros is one solution to the overhead problem. However, macros are not really functions and therefore the usual error checking does not occur during compilation.

The C++ solution: inline functions

To eliminate the cost of calls to small functions, C++ proposes a new feature called the inline function.

An inline function is a function that is expanded in line when it is invoked — that is, the compiler replaces the function call with the corresponding function code.

General form
inline function-header
{
    function body
}
Real example
inline double cube(double a)
{
    return (a * a * a);
}

c = cube(3.0);        // becomes 3.0*3.0*3.0
d = cube(2.5 + 1.5);  // correct, unlike a macro

Before and after

Normal function — 4 steps per call
int add(int a, int b)
{
    return a + b;
}

int main()
{
    int x = 5, y = 10;
    int result = add(x, y);
    cout << "Result: " << result;
    return 0;
}
Inline — no call at all
inline int add(int a, int b)
{
    return a + b;
}

int main()
{
    int x = 5, y = 10;
    int result = add(x, y);   // becomes x + y
    cout << "Result: " << result;
    return 0;
}

On the left, calling add(x, y) involves: 1. pushing x and y onto the stack, 2. transferring control to add, 3. executing return a + b, 4. returning to main. On the right, the compiler replaces the call with x + y directly inside main. There is no overhead.

A complete program

The rules

  • To make a function inline, prefix the keyword inline to the function definition.
  • All inline functions must be defined before they are called.
  • The speed benefits of inline functions diminish as the function grows in size.
  • At some point the overhead of the function call becomes small compared to the execution of the function, and the benefits of inlining may be lost.
  • Hence, usually functions are made inline when they are small enough to be defined in one or two lines.
When to use inline
  • Small, frequently called functions
  • Where call overhead is significant compared to the function's execution time
  • Simple getters and setters
  • Small mathematical operations
The drawback: code bloat
  • If the inline function is large or called many times, each call gets its own copy of the code
  • This increases binary size
  • Which can hurt performance through increased cache usage and memory footprint
Worth remembering

inline is a request, not a command. The compiler may ignore it — for example if the function has a loop, a switch, or is recursive. Ask for it; do not assume you got it.

Default arguments

C++ lets you give a function argument a default value, so that callers who do not care about it can simply leave it out.

defaultargs.cpp
#include <iostream>
using namespace std;

int sum(int n1, int n2, int n3 = 0, int n4 = 0);   // defaults go HERE

int main()
{
    int s1, s2, s3;

    s1 = sum(10, 20);              // n3 and n4 become 0
    s2 = sum(10, 20, 30);          // n4 becomes 0
    s3 = sum(10, 20, 30, 40);      // nothing defaulted

    cout << s1 << endl << s2 << endl << s3 << endl;
    return 0;
}

int sum(int n1, int n2, int n3, int n4)            // NOT here
{
    return (n1 + n2 + n3 + n4);
}
Output
30
60
100

The three rules

  1. The default values are mentioned only in the function prototype, and not in the function definition. The compiler uses the prototype information to build a call, not the function definition.
  2. Default values can be assigned only for trailing arguments — the ones at the end — and not to leading arguments or arguments in the middle.
  3. The default value for an argument can be a global constant, a global variable, or even a function call.
Illegal — gap in the middle
int sum(int n1, int n2, int n3 = 0, int n4);
Legal — a function call as default
int myfunc (int flag = display());
In plain words — why rule 2 exists

Suppose sum(int a, int b = 5, int c) were legal, and someone wrote sum(1, 2). Is 2 the value of b or of c? The compiler cannot tell. Arguments are matched left to right, so the ones you may omit must all be at the right-hand end.

When default arguments are useful

Your materials give two specific cases:

  • When you do not want the trouble of writing arguments that almost always have the same value. For example, bank interest will remain the same for all customers for a particular period of deposit.
  • When you want to extend an existing function. After having written a program, you may decide to increase the capability of a function by adding another argument. Using default arguments means that the existing function calls can continue to use the old number of arguments, while new function calls can use more.
Worth remembering

The second reason is the important one in real software: default arguments let you add a parameter without breaking any code that already calls the function. That is a genuinely valuable property and a good exam answer.

A recursive function is one that calls itself. Your materials give two classic examples: calculating the factorial of a number, and solving the Tower of Hanoi problem.

    }
}

How it unwinds

Tracing fact(5)

                            fact(3) = 3 * fact(2)
                                          fact(2) = 2 * fact(1)

Worth remembering — every recursive function needs two things
  • A base case — a condition where it stops calling itself and simply returns. Here it is if (n == 0) return 1;
  • A recursive case that moves towards the base case. Here fact(n-1) makes n smaller each time.

Leave out the base case and the function calls itself forever until the stack runs out. That crash is called a stack overflow.

Tower of Hanoi

The second classic. With 3 disks on tower 1, moving them all to tower 2 takes these steps:

Solution for 3 disks
There are 3 disks in tower 1
Shift top disk from tower 1 to tower 2
Shift top disk from tower 1 to tower 3
Shift top disk from tower 2 to tower 3
Shift top disk from tower 1 to tower 2
Shift top disk from tower 3 to tower 1
Shift top disk from tower 3 to tower 2
Shift top disk from tower 1 to tower 2

3 disks in tower 1 are shifted to tower 2.

Seven moves for three disks. The pattern is 2n − 1 moves for n disks — which is why the puzzle becomes impossible very quickly as n grows.

Chapter 35

Function overloading

This is your first taste of real polymorphism, and it is a pure C++ feature.

The problem

In C, every function in a program has a unique name. However, in some situations it seems unnecessary to have different function names if the task performed by them is the same.

Three functions doing the same job
int    absolute(int i);
long   absolute(long l);
double absolute(double d);

C++ overcomes this situation by allowing the programmer to create three different functions with the same name. This is called function overloading.

How the compiler chooses

How does the C++ compiler know which of the absolute functions should be called when a call is made? It decides that from the type of argument being passed during the function call.

Types the compiler was not given
char  ch = absolute('A');      // no char version exists
float f  = absolute(3.14f);    // no float version exists

As we have not defined the absolute function to handle the character and floating point value, the C++ compiler calls the integer version for the character, and the double version for the floating value. It promotes the argument to the nearest type it does have.

In plain words

The compiler plays matchmaker. It looks at what you passed and finds the closest available function. An exact match wins. If there is no exact match, it will promote a smaller type to a bigger one — char becomes int, float becomes double.

Rule 1 — the return type is not enough

The overloaded functions must at least differ in the type, number or order of parameters they accept. Difference only in return type is not enough to consider them as overloaded functions.

This will not compile
#include <iostream>
using namespace std;

int      stringToNumber (char *);     // same parameters,
long int stringToNumber (char *);     // only return type differs — ERROR

int main()
{
    int      n1;
    long int n2;
    char *ptr1 = "155";
    char *ptr2 = "400000";

    n1 = stringToNumber (ptr1);
    n2 = stringToNumber (ptr2);
    cout << n1 << endl << n2;
    return 0;
}
Careful — why this fails

Think about the call stringToNumber(ptr1); written on its own line, with the result thrown away. The compiler sees only the argument, which is identical for both versions. It has no way to choose. So C++ forbids overloading on return type alone.

Rule 2 — typedef does not create a new type

Can we fool the C++ compiler into believing that two data types are different by renaming one of them using typedef?

No. A typedef merely gives another name for an existing type and does not constitute a different type.

Also will not compile
typedef int INT;

void display(int);
void display(INT);    // INT is just another name for int — ERROR

Here INT is just another name for an int. Hence the compiler cannot differentiate between the two versions of display().

Rule 3 — const does create a difference

This one does work. A pointer to a string and a pointer to a constant string are genuinely different types.

Overloading on const — legal
#include <iostream>
using namespace std;

void display (char *);
void display (const char *);

int main()
{
    char       *ch1 = "Hello";
    const char *ch2 = "Bye";

    display (ch1);      // calls the first version
    display (ch2);      // calls the second version
    return 0;
}

void display (char *p)
{
    cout << p << endl;
}

void display (const char *p)
{
    cout << p << endl;
}

The first version of display() receives a pointer to a string, whereas the second receives a pointer to a constant string.

Chapter 36

Declaring a class

A class is a user-defined data type that serves as a blueprint for creating objects. It encapsulates data (attributes) and methods (functions) that operate on that data within a single unit.

The general form

General form
class ClassName
{
public:
    // Member variables (attributes)
    dataType attributeName1;
    dataType attributeName2;
    // ...

    // Member functions (methods)
    returnType methodName1(parameters);
    returnType methodName2(parameters);
    // ...
};
PartWhat it means
classThe keyword used to declare a class.
ClassNameThe name of the class. Follows the same rules as variable naming.
public:An access specifier. public makes the members accessible from outside the class.
private:, protected:Other access specifiers. private makes members accessible only within the class itself; protected allows access from within the class and its derived classes.
dataTypeThe data type of the member variable, or the return type of the member function.
attributeName1Names of member variables (attributes).
returnTypeThe data type returned by the member function.
methodName1Names of member functions (methods).
parametersThe input parameters the member function may take.
Careful — the most common syntax error in the whole course

A class declaration ends with a semicolon after the closing brace: }; — not just }. Forgetting it produces a wall of confusing errors that point at the next line, not at the class.

The complete example from your material

The item class
class item
{
    int   number;     // variables declaration
    float cost;       // private by default

public:
    void getdata(int a, float b);   // functions declaration
    void putdata(void);             // using prototype
};

public vs private — the whole point of OOP

Notice that number and cost appear before any access specifier. In a class, members are private by default. That means only the class's own functions can touch them.

private
  • The default in a class
  • Accessible only within the class itself
  • Objects cannot reach these members
  • This is where your data belongs
public
  • Must be written explicitly
  • Accessible from outside the class
  • Objects can call these
  • This is where your functions belong

Creating objects

Once the class exists, you create objects from it. There are two ways.

Way 1 — after the class
class item
{
    // ...
};

item x;           // one object
item x, y, z;     // three objects
Way 2 — in the declaration
class item
{
    int   number;
    float cost;
public:
    void getdata(int a, float b);
    void putdata(void);
} x, y, z;        // objects created here

What an object may and may not do

Legal
x.getdata(100, 75.5);
x.putdata();
Illegal
x.number = 100;   // number is private
x.cost   = 75.5;  // cost is private
Worth remembering — state it in exactly these words

Objects cannot access the private members of a class directly. They must go through a public member function. That is encapsulation working. In the example, x cannot set number itself, but it can ask getdata() to do it — and getdata() could check the value first.

A full working class

rectangle.cpp
#include <iostream>
using namespace std;

class Rectangle
{
public:
    int width;
    int height;

    int calculateArea()
    {
        return width * height;
    }

    void setDimensions(int w, int h)
    {
        width  = w;
        height = h;
    }
};

int main() {
    Rectangle rect1, rect2;

    rect1.setDimensions(5, 10);
    rect2.setDimensions(3, 7);

    int area1 = rect1.calculateArea();   // 50
    int area2 = rect2.calculateArea();   // 21

    cout << "Area of Rectangle 1 is : \n" << area1 << endl;
    cout << "Area of Rectangle 2 is : \n" << area2 << endl;

    return 0;
}
Output
Area of Rectangle 1 is :
50
Area of Rectangle 2 is :
21

Notice the key fact: rect1 and rect2 were made from the same class, but each has its own separate width and height. Setting rect1 to 5×10 did nothing to rect2.

Chapter 37

Member functions

There are two ways to write the body of a member function: outside the class definition or inside the class definition. Both produce identical behaviour.

Outside the class — using ::

This is the form you will use most, because it keeps the class declaration short and readable.

General form
return-type class-name :: function-name
                          (argument declaration)
{
    Function body
}
Real example
void item :: getdata(int a, float b)
{
    number = a;
    cost   = b;
}

The full example from your material:

Both member functions defined outside
void item :: getdata(int a, float b)
{
    number = a;
    cost   = b;
}

void item :: putdata(void)
{
    cout << "Number :" << number << endl;
    cout << "Cost :"   << cost   << endl;
}

The membership label item :: tells the compiler that this function belongs to the class item. That is what gives the function permission to touch the private members number and cost.

In plain words

Think of item::getdata as a full postal address and getdata as just a house number. Many classes might have a getdata; the item:: part says which one this is.

Three characteristics of a member function defined outside
  • Several different classes can use the same function name. The membership label resolves the scope.
  • Member functions can access the private data of the class. A non-member function cannot.
  • A member function can call another member function directly, without using the dot operator.

Inside the class — automatically inline

When you write the body inside the class definition, the function is treated as an inline function automatically. You do not write the keyword.

Defined inside the class
class item
{
    int   number;
    float cost;

public:
    void getdata(int a, float b);   // declaration only

    void putdata(void)              // definition inside
    {
        cout << number << endl;
        cout << cost   << endl;
    }
};

Normally only small functions are defined inside the class definition — which fits perfectly with what you learned about inline functions in Chapter 32.

Making an outside function inline explicitly

You can have it both ways: define the function outside for readability, and still ask for it to be inlined.

Explicit inline member function
class item
{
    int   number;
    float cost;
public:
    void getdata(int a, float b);
};

inline void item :: getdata(int a, float b)
{
    number = a;
    cost   = b;
}

Nesting of member functions

A member function can be called by another member function of the same class. This is known as nesting of member functions — and no dot operator is needed.

One member function calling another
class sample
{
    int  m;
    void read(void);      // PRIVATE member function

public:
    void update(void);
    void write(void);
};

void sample :: update(void)
{
    read();               // calling a private member function
}

Private member functions

Data is normally private, but a function can be private too. You would do this for a helper function that should never be called from outside — an internal detail of how the class works.

What an object may not do
sample S1;
S1.read();     // WON'T WORK — read() is private
Worth remembering

A private member function can only be called by another function that is a member of its class. Even an object of that same class cannot call it directly. The only way in is through a public function like update(), which then calls read() internally.

Chapter 38

Arrays inside a class

An array can be used as a data member of a class, exactly like any other variable. The array is then private, so only the class's own functions can read or write its elements.

An array as a class member
const int size = 50;

class array
{
    int arr[size];        // private array

public:
    void setval(void);
    void display(void);
};

The array arr contains 50 integers, and it is private. Only setval() and display() can get at it, so no code outside the class can accidentally write past the end of the array or corrupt its contents.

A worked example — a simple marks store
#include <iostream>
using namespace std;

const int size = 5;

class marks
{
    int arr[size];
    int count;

public:
    void setval(void)
    {
        count = 0;
        for (int i = 0; i < size; i++)
        {
            cout << "Enter mark " << i + 1 << ": ";
            cin  >> arr[i];
            count++;
        }
    }

    void display(void)
    {
        int total = 0;
        for (int i = 0; i < count; i++)
        {
            cout << "Mark " << i + 1 << " = " << arr[i] << endl;
            total = total + arr[i];
        }
        cout << "Total = " << total << endl;
    }
};

int main()
{
    marks m1;
    m1.setval();
    m1.display();
    return 0;
}
In plain words

Notice that count and arr travel together. Outside code can never set count to a wrong value and make display() read past the end of the array. That safety is exactly what you were promised in Chapter 09 — and here it is, actually happening.

Chapter 39

Memory allocation for objects

This question is asked constantly: if I make ten objects of a class, do I get ten copies of the member functions too? The answer is no — and understanding why makes the rest of the course easier.

The rule

  • Member functions are created and placed in memory only once, when the class is defined.
  • All objects belonging to that class share that one copy of each member function.
  • Space for member variables is allocated separately for each object, because the member variables hold different values in different objects.
What memory actually looks like
          Common for all objects
        +--------------------------+
        |    member function 1     |
        |    member function 2     |     <-- ONE copy, shared
        +--------------------------+

  object 1              object 2              object 3
+-------------+      +-------------+      +-------------+
| member var1 |      | member var1 |      | member var1 |
| member var2 |      | member var2 |      | member var2 |
+-------------+      +-------------+      +-------------+
  own memory           own memory           own memory
In plain words

The recipe for making tea is written once in the cookbook. A hundred people can follow it. But each person needs their own cup. The recipe is the member function; the cup is the member variable.

Worth remembering

Memory space for member variables is allocated separately for each object; member functions are stored once and shared by all objects of the class. That single sentence is a complete answer to a very common exam question.

Arrays of objects

Since a class is a data type, you can make an array of objects just as you would make an array of int.

Arrays of employee objects
employee manager[3];     // array of 3 manager objects
employee developer[15];  // array of 15 developer objects
employee tester[30];     // array of 30 tester objects

The array manager contains three objects, named manager[0], manager[1] and manager[2], each of type employee. You call member functions on them with the dot operator as usual:

Using an array of objects
for (int i = 0; i < 3; i++)
{
    manager[i].getdata();
}

for (int i = 0; i < 3; i++)
{
    manager[i].putdata();
}

Chapter 40

static data members and member functions

Normally every object gets its own copy of every data member. A static member breaks that rule on purpose: one copy, shared by every object of the class.

static data members

The four properties
  • It is initialised to zero when the first object of its class is created. No other initialisation is permitted.
  • Only one copy of that member is created for the entire class and is shared by all the objects of that class, no matter how many objects are created.
  • It is visible only within the class, but its lifetime is the entire program.
  • It must be defined outside the class to actually allocate storage for it.
Defining it outside
type class-name :: member-name = value;
Real example
int item :: count = 10;

A complete counter

staticcount.cpp
#include <iostream>
using namespace std;

class item
{
    static int count;    // declared, NOT defined
    int number;

public:
    void getdata(int a)
    {
        number = a;
        count++;         // shared across all objects
    }

    void getcount(void)
    {
        cout << "count: " << count << endl;
    }
};

int item :: count;       // definition — storage happens here

int main()
{
    item a, b, c;        // three objects

    a.getcount();        // count is 0
    b.getcount();
    c.getcount();

    a.getdata(100);
    b.getdata(200);
    c.getdata(300);

    cout << "After reading data" << endl;

    a.getcount();        // all three now show 3
    b.getcount();
    c.getcount();

    return 0;
}
Output
count: 0
count: 0
count: 0
After reading data
count: 3
count: 3
count: 3

This is the proof. Objects a, b and c each have their own number, but they all read the same count. Each call to getdata() incremented the one shared copy.

Careful

The line int item :: count; outside the class is not optional. Inside the class you only declare that a static member exists. If you leave out the outside definition, the program compiles but fails at link time with "undefined reference to item::count".

static member functions

A member function can also be declared static. Such a function has two restrictions:

  • A static member function can have access only to other static members — functions or variables — declared in the same class.
  • A static member function can be called using the class name instead of an object.
General form of the call
class-name :: function-name();
Real example
item :: getcount();   // no object needed
In plain words — why the restriction makes sense

A static function can be called without any object existing. So if it tried to read number, the compiler would have to ask: whose number? There is no object to ask. That is exactly why a static function may only touch static data — static data belongs to the class, not to any object.

Worth remembering

A perfect use case for a static member: counting how many objects of a class currently exist. No single object can know this, because it is a fact about the class as a whole. That is the standard exam example, and it is the program above.

Chapter 41

Objects as arguments and return values

An object is a data type like any other, so it can be passed into a function and handed back out of one.

Passing an object to a function

An object may be used as a function argument in two ways:

  • A copy of the entire object is passed to the function — this is pass by value. Since a copy is made, changes made to the object inside the function do not affect the object used in the call.
  • Only the address of the object is transferred to the function — this is pass by reference. Here, changes made to the object inside the function will affect the original object, since they are on the same object.
Object passed by value
void calculateAverage(Student s1, Student s2)
{
    // s1 and s2 are COPIES
}
By value — original safe
void raise(Student s)
{
    s.marks = s.marks + 10;
}
// caller's object unchanged
By reference — original changed
void raise(Student &s)
{
    s.marks = s.marks + 10;
}
// caller's object IS changed

Returning an object from a function

A function can also hand an object back.

Returning an object
Student createStudent()
{
    Student student;
    // fill in the student here
    return student;
}

A complete example — adding two complex numbers

This program uses both ideas at once: an object goes in as an argument, and a fresh object comes back as the result.

complexadd.cpp
#include <iostream>
using namespace std;

class complex
{
    float x;     // real part
    float y;     // imaginary part

public:
    void input(float real, float imag)
    {
        x = real;
        y = imag;
    }

    // takes an object IN, hands an object BACK
    complex sum(complex c)
    {
        complex temp;
        temp.x = x + c.x;     // x is this object's; c.x is the argument's
        temp.y = y + c.y;
        return temp;
    }

    void show(void)
    {
        cout << x << " + j" << y << endl;
    }
};

int main()
{
    complex c1, c2, c3;

    c1.input(2.5, 3.5);
    c2.input(1.6, 2.7);

    c3 = c1.sum(c2);     // c1 is the caller, c2 is the argument

    cout << "c1 = "; c1.show();
    cout << "c2 = "; c2.show();
    cout << "c3 = "; c3.show();

    return 0;
}
Output
c1 = 2.5 + j3.5
c2 = 1.6 + j2.7
c3 = 4.1 + j6.2
Worth remembering — the one surprising rule

Inside sum(), the line temp.x = x + c.x; reads c.x — a private member of a different object. Is that allowed? Yes. Privacy in C++ is per class, not per object. A member function of complex can reach the private members of any complex object, not just its own.

In plain words

Remember this program. In Chapter 48 you will rewrite the exact same thing so that you can simply write c3 = c1 + c2; instead of c3 = c1.sum(c2);. That is what operator overloading buys you, and comparing the two versions is the fastest way to understand it.

Friends and pointers to members

Two escape hatches. The first lets a chosen outsider reach inside a class. The second lets you point at a member of a class the way you point at a variable.

Chapter 42

Friend functions

We spent all of Part VI learning that private data is private. A friend function is the deliberate exception — a non-member function that the class explicitly grants access to.

What a friend function is

  • A friend function is a function that is not a member of a class but has access to the class's private and protected members.
  • Friend functions are not considered class members; they are ordinary external functions that are given special access privileges.
  • Friend functions are not in the class's scope, and they are not called using the dot operator. A friend function can be called like a normal function, without any object.
  • A friend function cannot access member names directly — it has to use an object name and the dot operator with each member name, like A.x.

The syntax

General form
class className
{
    ... .. ...
    friend returnType functionName(arguments);
    ... .. ...
};
Real example
class MyClass
{
    int member1;
    friend int init (MyClass);
};

int init(MyClass obj)
{
    obj.member1 = 5;      // allowed — it is a friend
    return obj.member1;
}
Careful — where the keyword goes

The word friend appears only inside the class declaration. When you write the actual function definition later, you do not repeat friend, and you do not write MyClass:: — because it is not a member of the class.

A complete working example

friendfn.cpp
#include <iostream>
using namespace std;

class sample
{
    int a;
    int b;

public:
    void setvalue()
    {
        a = 25;
        b = 40;
    }

    friend float mean(sample s);   // declared a friend
};

float mean(sample s)               // no "friend", no "sample::"
{
    return float(s.a + s.b) / 2.0;  // reaches private a and b
}

int main()
{
    sample X;
    X.setvalue();

    cout << "Mean value = " << mean(X) << endl;   // called like a normal function

    return 0;
}
Output
Mean value = 32.5

Three things to notice, and they are all examinable:

  1. mean reads s.a and s.b, which are private. Only the friend declaration makes this legal.
  2. The call is mean(X), not X.mean(). It is not a member, so there is no dot.
  3. Inside, it must write s.a — it cannot write bare a, because it has no object of its own.

Making a member function of another class a friend

You can be more precise than granting friendship to a free function: you can name a single member function of another class as the friend.

One member function as friend
class X
{
    ...
    int fun1();
    ...
};

class Y
{
    ...
    friend int X :: fun1();    // only fun1 of class X is a friend
    ...
};

The function fun1() of class X is a friend of class Y. No other function of X gets access. This is the tightest form of friendship and is the one to prefer.

Friend classes

If you want all the member functions of one class to have access to another class, declare the whole class a friend.

A whole class as friend
class Z
{
    ...
    friend class X;    // every member function of X is now a friend of Z
    ...
};

Forward declaration

Sometimes a class must be mentioned before it has been fully defined — for example when two classes refer to each other. For this you use a forward declaration: you tell the compiler "a class with this name exists, details to follow".

Forward declaration
class ABC;    // forward declaration — just the name

Where friends are genuinely useful

The real reason friends exist is in operator overloading, and you will meet it properly in Chapter 49. The short version: a member operator function always takes its left operand from the object it belongs to. So A = B + 2; works, but A = 2 + B; fails — because 2 is not an object and has no member functions. A friend function takes both operands as explicit arguments, so both orders work.

Worth remembering

The standard exam framing is: "A friend function breaks encapsulation, so why does C++ allow it?" Answer: because some operations are genuinely symmetric between two classes, or between a class and a built-in type, and forcing them to be a member of one side would be artificial. Friendship is granted by the class itself, in its own declaration — so the class still controls who gets in. It is a controlled exception, not a hole.

Careful — three properties of friendship
  • Friendship is granted, not taken. A function cannot declare itself a friend of a class.
  • Friendship is not mutual. If A declares B a friend, that does not make A a friend of B.
  • Friendship is not inherited. A friend of a base class is not automatically a friend of a derived class.

Chapter 43

const member functions

If a member function does not modify the object it belongs to, you can — and should — say so by marking it const. The compiler then enforces the promise.

General form
return_type class_name :: function_name() const
{
    // body — may not modify any data member
}
Declaration inside the class
class item
{
    int number;
public:
    int getdata() const;    // const goes at the END
};

The const keyword goes after the argument list, before the body. Both the declaration and the definition must carry it.

A const member function in full
#include <iostream>
using namespace std;

class item
{
    int number;
    float cost;

public:
    void setdata(int n, float c)
    {
        number = n;
        cost   = c;
    }

    int getnumber() const      // promises not to change anything
    {
        return number;
    }

    void show() const
    {
        cout << number << " costs " << cost << endl;
    }
};

int main()
{
    item i1;
    i1.setdata(101, 45.5);
    cout << "Number is " << i1.getnumber() << endl;
    i1.show();
    return 0;
}
Output
Number is 101
101 costs 45.5
Careful — the compiler will stop you

If you write number = 5; inside a function marked const, the program will not compile. That is the point. The const is a promise checked at compile time, not a comment.

Worth remembering

Mark every "getter" or display function const. Two reasons:

  • It documents your intent — the reader knows at a glance that this function is safe.
  • A const object can only call const member functions. If you forget the const, your function becomes unusable on const objects and on const references.

Chapter 44

Pointers to members

C++ permits us to define a class containing various types of data and functions as members. It also permits us to access those class members through pointers. To do this, C++ provides a set of three pointer-to-member operators.

OperatorWhat it does
::*To declare a pointer to a member of a class.
.*To access a member using an object name and a pointer to that member.
->*To access a member using a pointer to the object and a pointer to that member.

First, the ordinary pointer to an object

Before the new operators, remember the plain case. A pointer can point at an object, and then you reach members with ->:

Pointer to an object
class Simple
{
public:
    int a;
};

int main()
{
    Simple obj;
    obj.a = 10;

    Simple* ptr;
    ptr = &obj;

    cout << ptr->a;    // 10
    return 0;
}

Pointer to a data member

This is different. Here the pointer does not point at an object — it points at a member slot that exists in every object of the class.

General form
datatype class_name :: *pointer_name;

pointer_name = &class_name :: datamember_name;
Real example
int A :: *ip = &A :: m;

The line int A::*ip = &A::m; reads as: "ip is a pointer to an int member of class A, and it points at the member called m." Note that m must be public for this to be written outside the class.

Using it with .* and ->*

With an object — use .*
A a;
cout << a.*ip;
With a pointer to object — use ->*
A *ap = &a;
cout << ap->*ip;

A complete program

ptrmember.cpp
#include <iostream>
using namespace std;

class Data
{
public:
    int a;

    void print()
    {
        cout << "a = " << a << endl;
    }
};

int main()
{
    Data  d;
    Data *dp = &d;

    int Data::*ptr = &Data::a;   // pointer to the member 'a'

    d.*ptr  = 10;                // set through an object
    d.print();                   // a = 10

    dp->*ptr = 20;               // set through a pointer to object
    dp->print();                 // a = 20

    return 0;
}
Output
a = 10
a = 20

Pointer to a member function

The same idea applied to functions. The syntax looks heavier because the pointer must also record the return type and the argument types.

Declare and assign together
int (Data::*fp1) (float) = &Data::f;
Declare, then assign
int (Data::*fp2) (float);
fp2 = &Data::f;

Read int (Data::*fp1)(float) from the inside out: "fp1 is a pointer to a member function of Data that takes a float and returns an int."

Calling through a member function pointer
#include <iostream>
using namespace std;

class Data
{
public:
    int f(float x)
    {
        cout << "f called with " << x << endl;
        return 1;
    }
};

int main()
{
    Data  d;
    Data *dp = &d;

    int (Data::*fp)(float) = &Data::f;

    (d.*fp)(3.5);        // through an object
    (dp->*fp)(7.5);      // through a pointer to object

    return 0;
}
Output
f called with 3.5
f called with 7.5
Careful — the brackets are compulsory

You must write (d.*fp)(3.5); with the outer brackets. Without them, d.*fp(3.5) is parsed as d.*(fp(3.5)) — C++ gives the function-call brackets higher precedence than .*, so it tries to call fp first. This is a guaranteed compile error and a favourite trick question.

In plain words

A normal pointer stores an address. A pointer to a member stores an offset — "the third slot in whatever object you give me". That is why you always need two things to use it: the pointer-to-member and an object to apply it to. That is exactly what .* and ->* do — they join the two halves together.

Chapter 45

Constructors

A constructor is a special member function whose task is to initialise the objects of its class. It is called automatically the moment an object is created — you never call it yourself.

The four rules

A constructor must obey all four
  • It has the same name as the class itself.
  • It is called automatically when an object is created.
  • It has no return type — not even void.
  • It should be declared in the public section of the class.
General form
class Wall
{
public:

    {
        // body of constructor
    }
};
Real example
class integer
{

};

{
    m = 0;

}

When you now write:

Creating the object
integer int1;    // constructor runs automatically, m and n become 0

...the declaration not only creates the object int1 of type integer but also initialises its data members m and n to zero.

In plain words — why constructors exist

Without a constructor, a freshly created object contains whatever rubbish was already in that memory. A constructor guarantees that an object is never in an invalid state, not even for a single instruction. That is a big deal. It means you can never accidentally use an uninitialised object.

Often you want to initialise different objects with different values. C++ permits you to pass arguments to the constructor. Such constructors are called parameterized constructors.

Now you must supply the values when you create the object. There are two ways to do that.

Both do exactly the same thing. The second form is shorter and is the one you will normally see.

Careful

Constructors are functions, so they can be overloaded just like any other function. This is called multiple constructors in a class.

The copy constructor

A copy constructor is used to declare and initialise an object from another object of the same class. It has one rule that trips up almost everybody.

The rule that matters

Illegal
class A
{
public:
    A(A);     // ERROR — by value
};
Legal — this is a copy constructor
class A
{
public:
    A(A&);    // by reference
};
Worth remembering — why A(A) is illegal

Passing an object by value means making a copy of it. Making a copy means calling the copy constructor. So A(A) would have to call itself to build its own argument, which would call itself again, forever. The copy constructor must take its argument by reference. This is asked constantly.

Writing one

Copy constructor in a class
class integer
{
    int m, n;

public:
    integer()
    {
        m = 0;
        n = 0;
    }

    integer(int a, int b)
    {
        m = a;
        n = b;
    }

    integer(integer &i)     // the copy constructor
    {
        m = i.m;
        n = i.n;
    }
};

The four ways it gets called

Where a copy constructor runs
integer I2(20, 40);

integer I3(I2);      // 1. explicit copy — the common form
integer I4 = I2;     // 2. copy initialization — same thing

Beyond those two, the copy constructor also runs invisibly:

  1. When an object is passed to a function by value — the function's copy is built by the copy constructor.
  2. When an object is returned from a function by value.
Careful — the distinction people get wrong

integer I4 = I2; calls the copy constructor, because I4 is being created. But I4 = I2; on a later line, when I4 already exists, calls the assignment operator, not the copy constructor. Same symbol, two different jobs, decided by whether the object already exists.

A destructor is the opposite of a constructor. It is called automatically when an object is destroyed, and its job is to clean up.

The rules

A destructor
  • Has the same name as the class, preceded by a tilde ~.

  • Is called automatically when the object goes out of scope.

Chapter 48

Operator overloading

C++ lets you give an existing operator like + an additional meaning when it is applied to your own class. This is the second form of polymorphism, and it is what makes C++ classes feel like built-in types.

The idea

In Chapter 41 you wrote c3 = c1.sum(c2); to add two complex numbers. That works, but it reads badly. What you actually want is:

The goal
c3 = c1 + c2;

Operator overloading is how you get there. To define an additional task for an operator, you must specify what it means in relation to the class to which the operator is applied. This is done with a special function called an operator function.

The syntax

General form — outside the class
return-type classname :: operator op(arglist)
{
    Function body
}
General form — inside the class
class className
{
public:
    returnType operator symbol (arguments)
    {
        // body
    }
};

Three things make up the function name: the keyword operator, the operator symbol itself, and the argument list.

Adding two complex numbers

Worth remembering — the translation rule

For a member operator function, a + b becomes a.operator+(b). The left operand becomes the calling object, and the right operand becomes the argument. Once you see this, everything else about operator overloading follows — including why some things do not work, which is Chapter 49.

In plain words

The rules for operator overloading

The seven rules
  • Only existing operators can be overloaded. You cannot invent a new symbol.
  • The overloaded operator must have at least one operand that is a user-defined type.
  • You cannot change the basic meaning of an operator — you cannot make + mean subtraction for integers.
  • Overloaded operators follow the syntax rules of the original operators. Their precedence and associativity cannot be changed.
  • The number of operands cannot be changed. A unary operator stays unary; a binary operator stays binary.
  • Some operators cannot be overloaded at all — see the list below.
  • Some operators cannot be overloaded using a friend function — see Chapter 49.

Chapter 49

Member function or friend function?

An operator can be overloaded in two ways: as a member function of the class, or as a friend function. They are not interchangeable, and knowing when each one works is the point of this chapter.

The two translations

Member function
C3 = C1 + C2;

// becomes
C3 = C1.operator+(C2);

// left operand = calling object
// right operand = argument
// takes ONE argument
Friend function
C3 = C1 + C2;

// becomes
C3 = operator+(C1, C2);

// BOTH operands are arguments
// takes TWO arguments

The situation where a member function fails

Suppose you want to add a plain number to an object. With a member function:

This works
A = B + 2;

// becomes B.operator+(2)
// B is an object -> it has member
// functions -> fine
This fails
A = 2 + B;

// would become 2.operator+(B)
// 2 is an int. An int has no
// member functions. ERROR.
Worth remembering — the key sentence

A = 2 + B; fails with a member function but works with a friend function. With a friend, it simply becomes operator+(2, B) — an ordinary two-argument function call, and there is no requirement that the first argument be an object. This is exactly why friend functions exist, and it is the most commonly asked question on this topic.

Writing it both ways

Friend version — handles both orders
#include <iostream>
using namespace std;

class Complex
{
    float real, imag;

public:
    void input(float r, float i)
    {
        real = r;
        imag = i;
    }

    // two friends, one for each order
    friend Complex operator + (Complex c, float n);
    friend Complex operator + (float n, Complex c);

    void show()
    {
        cout << real << " + j" << imag << endl;
    }
};

Complex operator + (Complex c, float n)    // object + number
{
    Complex temp;
    temp.real = c.real + n;
    temp.imag = c.imag;
    return temp;
}

Complex operator + (float n, Complex c)    // number + object
{
    Complex temp;
    temp.real = n + c.real;
    temp.imag = c.imag;
    return temp;
}

int main()
{
    Complex B, A1, A2;
    B.input(3.0, 4.0);

    A1 = B + 2.0;      // works
    A2 = 2.0 + B;      // ALSO works, thanks to the friend

    cout << "B + 2 = ";  A1.show();
    cout << "2 + B = ";  A2.show();

    return 0;
}
Output
B + 2 = 5 + j4
2 + B = 5 + j4

How many arguments each form takes

Operator kindAs a member functionAs a friend function
Unary (one operand)0 arguments1 argument
Binary (two operands)1 argument2 arguments

The pattern is simple: a friend function always needs one more argument than the member version, because it has no calling object to supply the left operand.

Which should you use?

Use a member function when
  • The left operand is always an object of your class
  • The operator modifies the object — =, +=, ++
  • The operator must be a member: =, (), [], ->
Use a friend function when
  • The left operand may be a built-in type — 2 + B
  • You want both operand orders to work
  • The operation is symmetric and belongs to neither side
Careful

Four operators must be overloaded as member functions and can never be friends: =   ()   []   ->. Do not confuse this list with the four from Chapter 48 that cannot be overloaded at all (::, ., .*, ?:). Two different lists, both examinable.

Part IX

Inheritance: extending classes

The feature the whole of OOP is built around. One class hands its work to another, and the second one only writes what is different.

Chapter 51

What inheritance is, and why it exists

Your lecture opens with one word: reusability. It is always nicer to reuse something that already exists than to build the same thing again — and a class that has already been tested, debugged and used many times is worth a great deal.

The definition

C++ supports reuse by letting you create new classes out of existing ones. The mechanism of deriving a new class from an old one is called inheritance, or derivation.

Put in the words of the slide: the capability of a class to derive properties and characteristics from another class is called inheritance.

The old classThe new class
Base classDerived class
Parent classChild class
Super classSub class
In plain words

When we say the derived class inherits the base class, we mean it gets all the usable properties of the base class without changing the base class in any way, and may then add features of its own. The base class does not know or care that it has been inherited.

The is-a test

Inheritance is an is-a relationship. Use it only when that sentence is actually true:

  • A car is a vehicle.
  • An orange is a fruit.
  • A surgeon is a doctor.
  • A dog is an animal.
Careful

"A car has an engine" is not an is-a relationship, so Car should not inherit from Engine — it should simply hold an Engine as a member. Getting is-a and has-a the wrong way round is the commonest design mistake in this topic, and examiners ask about it.

Why bother — the three-class problem

Your slide gives the example. You need classes for Bus, Car and Truck. All three need fuelAmount(), capacity() and applyBrakes(), and the code for those three is the same in each.

Without inheritance
  • Write the three functions in Bus
  • Write them again in Car
  • Write them again in Truck
  • Fix a bug → fix it in three places
With inheritance
  • Write them once in Vehicle
  • Derive Bus, Car, Truck from it
  • Each adds only what is different
  • Fix a bug → fix it once

That is the whole argument. Inheritance, used to modify and extend the capabilities of existing classes, becomes a very powerful tool for incremental program development.

Worth remembering

Three benefits to quote: reusability (write once, use in many classes), extensibility (add to a class without touching it), and less code to maintain (one copy to fix). The cost is tighter coupling — changing the base class now affects everything derived from it.

Chapter 52

Writing a derived class

A derived class is defined by stating its relationship to the base class, and then adding its own details. The syntax is one line of punctuation you must get exactly right.

General form
class derived_name : mode base_name
{
    // members of the derived class
};
Real example
class Car : public Vehicle
{
    public:
        void horn();
};

Reading that line piece by piece

class
The keyword that creates a new class.
derived_class_name
The name of the new class, the one doing the inheriting.
:
The colon. It is what says "is derived from". Forget it and you have written two unrelated classes.
visibility mode
private, public or protected. It is optional, and if you leave it out the default is private.
base_class_name
The name of the existing class being inherited from. It must already be defined above this point.
Careful — the default is private

class Car : Vehicle and class Car : private Vehicle mean exactly the same thing. That is almost never what you want, because it hides everything from the outside. Write public explicitly unless you have a reason not to. (For a struct the default is the opposite — public.)

A complete single-inheritance program

Full program
#include <iostream>

        int wheels;

Chapter 53

The protected keyword

There is a problem with inheritance and private, and protected is the answer to it.

The problem

A private member of a base class cannot be inherited, so it is not available to the derived class at all. You could of course make it public so the derived class can reach it — but then it is reachable by every function in the program, and you have thrown away data hiding, which was the point of the class in the first place.

C++ therefore gives a third visibility modifier that serves exactly this limited purpose.

In plain words — what protected means

A member declared protected is accessible by the member functions within its own class and by any class immediately derived from it. It cannot be touched by anything outside those two. Think of it as "private to the family".

What happens to a protected member when it is inherited

Two sentences from the slide, and both are asked:

  • A protected member inherited in public mode stays protected in the derived class. It is therefore usable by that class's member functions and is still ready for further inheritance.
  • A protected member inherited in private mode becomes private in the derived class. It is still usable by that class's member functions, but it is not available for further inheritance.
Worth remembering

The keywords private, protected and public may appear in any order and any number of times inside a class declaration. There is no rule that private must come first — that is only a convention.

The three modes of inheritance

The visibility mode in class D : mode B does not change what the derived class can use. It changes what the derived class then passes on — to the outside world, and to anything derived from it in turn.

In plain words — how to remember it

The mode acts like a ceiling. Nothing can come through more open than the mode you wrote.

With public inheritance the ceiling is high, so everything keeps its own level. With protected the ceiling is "protected", so anything that was public gets pushed down to protected. With private the ceiling is "private", so everything ends up private.

And the top row never changes: private members of a base class are never inherited, whatever mode you use.

The two you will actually be asked to compare

  • They can be used by the member functions of the derived class
  • They are inaccessible to objects of the derived class
Publicly inherited
  • Public members of the base become public members of the derived class
  • They can be used by the member functions of the derived class
  • They are accessible to objects of the derived class

When a class inherits the attributes of two or more classes. It lets you combine the features of several existing classes as the starting point for a new one.

The most obvious problem with multiple inheritance, and a guaranteed exam question.

The problem in multiple inheritance

Suppose two base classes have a function with the same name, and the derived class does not override it. Call that function through an object of the derived class and the compiler shows an error — because it does not know which of the two you meant.

Chapter 58

Hybrid inheritance and the virtual base class

The fifth kind, and the one whose name carries a warning inside it.

What hybrid inheritance is

Hybrid inheritance is implemented by combining more than one type of inheritance — for example hierarchical inheritance together with multiple inheritance. Your slide titles it Hybrid (Virtual) Inheritance, and this chapter explains why that second word is there.

The shape — hierarchical, then multiple
        Student              <- one base
        /     \
       v       v             hierarchical
     Test    Sports
       \       /
        v     v              multiple
        Result

The trouble this shape causes

Test inherits Student. Sports also inherits Student. Result then inherits both — so Result ends up with two separate copies of everything Student owns, one arriving through each path.

Now roll is ambiguous again, but this time B1:: style resolution is hiding a real bug: the object genuinely holds two different roll values, and setting one does not set the other.

The fix: a virtual base class

Mark the shared base virtual in each of the classes that inherits it directly. C++ then keeps only one copy of it, shared by everything below.

Full program
#include <iostream>
using namespace std;

class Student
{
    protected:
        int roll;
    public:
        void setRoll(int r) { roll = r; }
};

class Test : virtual public Student      // note: virtual
{
    protected:
        float marks;
    public:
        void setMarks(float m) { marks = m; }
};

class Sports : virtual public Student    // note: virtual
{
    protected:
        float score;
    public:
        void setScore(float s) { score = s; }
};

class Result : public Test, public Sports
{
    public:
        void show()
        {
            cout << "Roll  : " << roll << endl;       // only ONE roll now
            cout << "Total : " << marks + score << endl;
        }
};

int main()
{
    Result r;
    r.setRoll(21);
    r.setMarks(78);
    r.setScore(9);
    r.show();
    return 0;
}

Roll  : 21
Total : 87
Careful

Remove the two virtual keywords and this program stops compiling — roll inside show() becomes ambiguous. The word virtual has to be written on the intermediate classes (Test and Sports), not on Result, because they are the ones doing the duplicating.

Worth remembering

The shape is often called the diamond problem. The one-line answer: when two classes derived from the same base are themselves inherited by one class, that class gets two copies of the base; declaring the base virtual keeps a single shared copy and removes the ambiguity.

Chapter 59

Inheritance: the whole thing on one page

Nine things. If you can say all nine without looking, you are ready for any inheritance question on the paper.

  1. What it is. Deriving a new class from an existing one, so the new class gets the old one's properties without changing it. Also called derivation. The point is reusability.
  2. The names. Old = base / parent / super. New = derived / child / sub. The test for using it at all is is-a.
  3. The syntax. class D : mode B { }; — the colon means "derived from", and the mode defaults to private if you leave it out.
  4. Private members are never inherited, in any mode. protected exists so that data can be hidden from the world but still reach the derived class.
  5. The mode is a ceiling. public keeps levels as they are; protected pushes public down to protected; private pushes everything to private.
  6. Five kinds: single, multilevel, hierarchical, multiple, hybrid.
  7. Constructor order in multiple inheritance: base classes first, in the order listed after the colon; destructors in reverse.
  8. Ambiguity. Same name in two bases → compiler error, fixed with obj.Base::func(). Same name in base and derived → no error, derived wins.
  9. The diamond. Two copies of a shared base; declare it virtual on the intermediate classes to keep one.

Quick self-test

A base class has a private member x. Can a publicly derived class use it?

No. Private members of a base class are never inherited, whatever the mode. The derived class can only reach x indirectly, through a public or protected member function of the base that returns it. If you want the derived class to touch it directly, declare it protected instead.

What is the access of a public base member after class D : protected B?

protected. The mode is a ceiling: nothing comes through more open than the mode. So a public member is pushed down to protected, and a protected member stays protected. Objects of D can therefore no longer call it, but anything derived from D still can.

What is printed, and in what order?
class A { public: A(){cout<<"A";} ~A(){cout<<"a";} };
class B { public: B(){cout<<"B";} ~B(){cout<<"b";} };
class C : public B, public A { public: C(){cout<<"C";} ~C(){cout<<"c";} };
with int main(){ C obj; }

BAC cab

Construction follows the order in the base list, which is B then A — not alphabetical order, and not the order the classes were declared in. So B, A, then C's own constructor: BAC.

Destruction is always the exact reverse: C, then A, then B: cab.

Why does class Car : Vehicle often fail to compile in main() even though it compiles as a class?

Because the missing mode defaults to private. The class itself is perfectly legal, and its own member functions can use everything they inherited — but every public member of Vehicle has become private inside Car, so main() can no longer call any of them through a Car object. Writing public explicitly fixes it.

Two classes Test and Sports both inherit Student, and Result inherits both. How many copies of Student's data does a Result object hold?

Two — one through each path — which is why any member of Student is ambiguous inside Result.

Declaring Student a virtual base class in both Test and Sports (: virtual public Student) reduces that to one shared copy and removes the ambiguity. This is the hybrid, or diamond, case.

Part I & II — foundations
Who created C++, and what was it originally called?

Bjarne Stroustrup created C++. It began life as "C with Classes" — the aim was to keep everything useful about C and add the ability to bundle data together with the functions that operate on it.

Name the four programming paradigms and say what a program "is" in each.

What is the single biggest weakness of procedure oriented programming?

Global data is exposed. Most functions share global data, and data moves openly around the system from function to function. Any function can change any piece of data, so a bug in one function can break an unrelated part of the program. Object oriented programming exists to fix exactly this.

List any five features of object oriented programming.
  • Emphasis is on data rather than procedure.
  • Programs are divided into objects.
  • Data structures are designed such that they characterise the objects.
  • Functions that operate on the data of an object are tied together in the same data structure.
  • Data is hidden and cannot be accessed by external functions.
  • Objects may communicate with each other through functions.
  • New data and functions can be easily added.
Part III & IV — tokens, types, operators
What is the difference between a structure and a union in terms of memory?

The size of a structure is greater than or equal to the sum of the sizes of its members — each member gets its own unique storage location. The size of a union is the size of its largest member, because all the members share the same piece of memory.

The consequence: in a structure, altering one member does not affect the others. In a union, altering any member alters the other members' values, and only one member can be accessed at a time.

What will enum color {red = 5, blue, green}; assign to each name?

red = 5, blue = 6, green = 7. Once you assign a value to one enumerator, the following ones continue counting up from there.

Why is *ip = *gp; invalid when gp is a void*?

A generic pointer can be assigned a pointer value of any basic data type, but it may not be dereferenced. It would make no sense to dereference a pointer to a void value — the compiler has no idea how many bytes to read or how to interpret them.

So gp = ip; is valid, but *ip = *gp; is not.

Why can an inline function be ignored by the compiler, and when should you use one?

inline is a request, not a command. The compiler may decline it — for example when the function contains a loop, a switch, or is recursive.

Use it for small, frequently called functions where the call overhead is significant compared to the function's execution time — simple getters and setters, or small mathematical operations. The benefit diminishes as the function grows, and a large inlined function called many times causes code bloat.

Why is int sum(int a, int b = 5, int c); illegal?

Default values can be assigned only for trailing arguments — never to leading arguments or arguments in the middle.

The reason: arguments are matched left to right. If someone wrote sum(1, 2), the compiler could not tell whether 2 was meant for b or for c. The arguments you may omit must all be at the right-hand end.

Can two functions be overloaded if they differ only in return type? Explain.

No. Overloaded functions must differ in the type, number or order of parameters. A difference only in return type is not enough.

The reason: consider a call written on its own line with the result discarded. The compiler sees only the arguments, which are identical for both versions, so it cannot choose.

Related trap: typedef int INT; does not create a new type, so display(int) and display(INT) are also not overloadable. But display(char*) and display(const char*) are, because those are genuinely different types.

Part VI & VII — classes, friends, pointers
If I create 10 objects of a class, how many copies of the member functions exist?

One. Member functions are created and placed in memory only once, when the class is defined, and all objects share that single copy.

Member variables are different: space for them is allocated separately for each object, because they hold different values in different objects.

Why must a static data member be defined outside the class?

Inside the class you only declare that the static member exists — no storage is allocated. The definition outside, written as int item :: count;, is what actually allocates the storage.

Leave it out and the program compiles but fails at link time with "undefined reference to item::count".

Remember also: a static member is initialised to zero when the first object is created, there is only one copy shared by all objects, and it is visible only within the class but lives for the entire program.

A friend function breaks encapsulation. Why does C++ allow it?

Because some operations are genuinely symmetric between two classes, or between a class and a built-in type, and forcing them to be a member of one side would be artificial.

The crucial safeguard: friendship is granted by the class itself, in its own declaration. A function cannot declare itself a friend. So the class still controls exactly who gets in. It is a controlled exception, not a hole.

Three properties to quote: friendship is granted, not taken; it is not mutual; and it is not inherited.

Part VIII — constructors and operators
Why must a copy constructor take its argument by reference?

Passing an object by value means making a copy of it, and making a copy means calling the copy constructor. So A(A) would have to call itself in order to build its own argument — which would call itself again, forever.

Therefore A(A); is illegal and A(A&); is legal.

In what order are objects destroyed, and when exactly?

In the reverse order of their creation, and at the closing brace of the block they were declared in.

So if A1, A2, A3 are created in main and A4 is created inside an inner block, then A4 is destroyed first — at the end of the inner block — and then A3, A2, A1 are destroyed in that order when main ends.

Why does A = 2 + B; fail with a member operator function but work with a friend?

For a member operator function, a + b is translated into a.operator+(b). The left operand becomes the calling object.

So 2 + B would become 2.operator+(B). But 2 is an int, and an int has no member functions. Compile error.

For a friend function, a + b becomes operator+(a, b) — an ordinary two-argument call, with no requirement that the first argument be an object. Both orders work.

Note also the argument counts: a friend function always needs one more argument than the member version. Unary: 0 as member, 1 as friend. Binary: 1 as member, 2 as friend.

Write a class that safely manages a dynamically allocated string.
Answer — the three essentials
class String
{
    char *p;
    int   len;

public:
    String(const char *s)          // 1. constructor: TAKE memory
    {
        len = strlen(s);
        p   = new char[len + 1];
        strcpy(p, s);
    }

    String(const String &s)        // 2. copy constructor: deep copy
    {
        len = s.len;
        p   = new char[len + 1];
        strcpy(p, s.p);
    }

    ~String()                      // 3. destructor: GIVE IT BACK
    {
        delete [] p;
    }
};

Any class that allocates memory with new needs its own copy constructor and destructor. Without the copy constructor, copying a String would copy the pointer, so two objects would point at the same memory — and when both destructors ran, that memory would be deleted twice and the program would crash.
