Read it this way

Four areas, every year, without exception. The DFT/FFT question, a difference equation, a z-transform with its ROC, and a frequency response. Those four are roughly 24 of the 30 marks. Everything else is the examiner’s choice of garnish.

The FFT question is the one that moves. 2023 asked for a radix-3 flow graph for N = 9. 2024 asked for operation counts including split-radix, and separately for DIT applied to the inverse DFT. 2025 asked for decimation in frequency on 16 points. So do not learn only the 8-point DIT butterfly — learn the counting formulas, both decimations, and what changes for a different radix.

Watch the ROC wording. Every year the z-transform question says “mention the ROC in all cases” or “find h(n) if the system is stable / causal / anti-causal”. It is asking for three separate answers from one algebraic H(z), and most of the marks are there rather than in the partial fractions.

2025 added something new: being handed a step response and asked to work backwards to the input. That is just differentiate-then-divide in the transform domain, and it is worth practising because it is an easy 7 marks once you see it.

The conclusion to write out

This system cannot be both causal and stable. Causal means the ROC is outside the outermost pole, |z| > 3, which excludes the unit circle. A causal system is stable only when every pole lies inside the unit circle, and the pole at z = 3 does not.

Q-4
Explain the decimation-in-time radix-2 FFT algorithm for an 8-point DFT. Draw the butterfly diagram, state the required input ordering, and count the complex multiplications and additions. Compare with the direct DFT.
Solution

The idea. Split x(n) into its even-indexed and odd-indexed samples. Each half is an N/2-point DFT, and the two are recombined with one twiddle multiplication per output:

X(k) = G(k) + W_N^k H(k) X(k + N/2) = G(k) - W_N^k H(k) for k = 0 .. N/2 - 1 G(k) = DFT of the even samples, H(k) = DFT of the odd samples

Repeat the split until only 2-point DFTs are left. For N = 8 that takes log28 = 3 stages, each with N/2 = 4 butterflies.

Input ordering — bit reversal. Splitting into evens and odds repeatedly leaves the input in bit-reversed order. Write each index in 3 bits and reverse them:

12 multiplications instead of 64 — about 5.3 times fewer

Say this about the saving

The saving grows with N, and fast: at N = 8 it is about 5×, at N = 512 it is 114×, and at N = 1024 it is 205×. That is why the algorithm was worth inventing — it turns an N² problem into an N·log N one.

Also worth a mark: the computation is in place. Each butterfly writes its two results back over the two inputs it just read, so no extra array is needed; bit reversal is the price paid for that.

Suppose we would like to find the N-point DFT where N = 3v. Develop a radix-3 decimation-in-time FFT algorithm, and draw the corresponding flow graph for N = 9. How many multiplications are required? Can the computation be performed in place?
Solution

The split. Radix-2 divides the input into two interleaved sets; radix-3 divides it into three, taken every third sample:

x(3r) r = 0 .. N/3 - 1 x(3r + 1) x(3r + 2)

Each subset gets an (N/3)-point DFT, and the three are recombined with twiddle factors:

X(k) = G0(k) + W_N^k G1(k) + W_N^2k G2(k) for k = 0 .. N/3 - 1, and then with W_N^(N/3) and W_N^(2N/3) rotations for the other two thirds of the output

complex multiplications ~ N (r - 1) / r x log_r N for N = 9, r = 3: = 9 x (2/3) x 2 = 12 complex multiplications against the direct DFT: N^2 = 81 speed-up ~ 6.75 times

Can it be done in place? Yes. Each radix-3 butterfly reads three values, computes three outputs, and writes them straight back over the same three locations. Nothing else in the array is touched, so no second array is needed — exactly as with radix-2. The digit-reversal shuffle is the price paid for it.

Why radix-3 exists at all

Radix-2 only works when N is a power of two. If your data length is naturally 9, 27 or 81, zero-padding up to 16, 32 or 128 changes the frequency grid. Radix-3 lets you keep the natural length. The same divide-and-conquer argument drives every radix — split the DFT into smaller DFTs and reuse the twiddle symmetry.
